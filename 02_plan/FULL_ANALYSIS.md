# 전체 분석 우선 — 사용자 지정 순서

## 현재 범위 — 2026-09-13 사용자 정정

현재 목표는 OPENSTEP 원본 커널의 분석에 한정한다. Mach4·NeXTMach·Darwin 등 다른
코드는 로컬 보존본을 포함하여 참고하지 않는다. 원본 바이너리와 그 바이너리에서 얻은
역어셈블·디컴파일·심볼·참조·메타데이터만 분석 근거로 사용한다.
디컴파일러가 붙인 타입·이름·제어 흐름은 원본 명령과 대조하기 전에는 확정하지 않는다.

기존 보고서의 외부 소스 비교는 이력으로 보존하되, 현재 원본 동작의 확정 근거에서 제외한다.
소스 복원·구현·빌드·다른 아키텍처 포팅은 현재 작업 범위 밖이다.
과거 GCC 2.7 요구는 향후 복원 시의 조건이며 현재 분석 완료를 빌드 작업으로 확장하지 않는다.
모든 주소·크기·개수·비트·해시 등의 계산은 Python으로 수행한다.

## 원본 분석 요구

구현·부분 소스 복원에 앞서 기준 바이너리 전체의 역어셈블과 디컴파일 자료를 확보한다.
함수 일부만 분석한 상태에서 다음 구현 단계로 전환하지 않는다.
범위는 현재 확보한 x86 mk-183.34.4이며, 향후 다른 아키텍처 바이너리도 별도 분석한다.

필수 산출물:

1. 해시가 일치하는 분석 프로젝트와 도구/loader/compiler-spec/분석 설정 기록.
2. 모든 로드 영역의 listing 및 code/data/undefined 분류와 원본 주소/파일 mapping.
3. 발견한 모든 함수의 본문 주소 범위, 전체 assembly, 디컴파일 출력, 상태/오류.
4. 심볼, 참조 관계, 타입/문자열 및 Objective-C 메타데이터의 분석 자료.
5. 함수 밖 instruction, 미식별 executable 영역, 디컴파일 실패를 재조사한 결과.
6. 원본 섹션 범위를 분모로 한 coverage 검증과 실패/미해결 목록.

도구가 인식한 함수만 모두 내보낸 것으로 전체 분석 완료를 선언하지 않는다.
미식별 영역은 코드·데이터·정렬을 증거로 구분하고, 잘못된 함수 경계나 누락 entry를 보완한다.
디컴파일 실패를 파일 생성 또는 빈 placeholder로 성공 처리하지 않는다.
asm-only 경로에 C 표현이 불가능한 경우에도 정확한 assembly와 기술적 원인/검토 근거를 남기며
미완료 디컴파일이 남아 있으면 사용자 목표 완료로 자동 판정하지 않는다.

기존 IDA DB 보존본은 변경하지 않고 별도 작업 DB를 사용한다.
Ghidra/Hex-Rays의 출력은 분석 자료이며 GCC 2.7용 복원 소스가 아니다.

## 자료 확보 결과

현재 x86 대상의 결과는 [전체 분석 보고서](../09_validation/reports/full-analysis/README.md)에 있다.
Ghidra 최종 자료는 `full-pass5`이며, export 이후의 Python 독립 검증을 별도로 보존했다.
IDA 보조 출력 실패와 디컴파일러 경고는 숨기지 않고 기록했다.
자료 확보 완료와 코드 의미·함수 경계·ABI 검증 완료는 서로 다른 판정이다.
