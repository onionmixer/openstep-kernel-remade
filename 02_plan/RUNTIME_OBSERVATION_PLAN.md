# x86 실기 런타임 관측 계획

작성: 2026-09-30. 상태: **R0–R4 완료(2026-09-30).**

## 범위와 결정 필요 사항

정적 증거 수집은 2026-09-26 기준으로 닫혔다([static-only closure](../09_validation/reports/multiarch-input-20260921/static-only-semantic-followup-closure-20260923.json)).
남은 보류 항목은 runtime 값, indirect/tail runtime target, structure/object layout 이며, 원본 bytes 만으로는 확정할 수 없다.

사용자가 OPENSTEP i386 실기를 쓸 수 있다고 알렸다(2026-09-30). 이 계획은 그 실기에서 **원본 커널을 바꾸지 않고 읽기만 하는** 관측을 정의한다.

[AGENTS.md](../AGENTS.md)와 HANDOFF 의 제약 5 는 현재 단계를 분석 전용으로 두고 실행으로의 확대를 막는다. 실행 중인 원본 커널의 메모리를 읽는 것은 구현·빌드·재부팅이 아니지만, **새로운 증거 종류(runtime memory)** 를 들이는 일이다. 따라서 R1 이후의 실행과 그 결과를 증거로 채택하는 것은 사용자 결정 뒤에 한다. 결과는 기존 정적 보고서와 섞지 않고 `09_validation/runtime/` 에 따로 둔다.

## R0 — 실기 신원 (완료, 읽기 전용)

[x86-identity-20260930.json](../09_validation/runtime/x86-identity-20260930.json)

- 실기 `/mach_kernel` 은 `03_original/x86/binaries/mach_kernel` 과 SHA-256 이 같다(`33469393…`).
- `hostinfo` 버전 문자열이 mk-183.34.4 RELEASE_I386 이다.
- `/dev/kmem` 의 `_hz`(0x1dee30) 4 바이트가 파일 값 100 과 같다.
- **아직 증명하지 않은 것:** 부팅된 이미지가 그 파일과 같다는 것. `/mach` 는 `$BOOTFILE` 링크이므로 R1 의 `__TEXT` 전체 대조로 증명한다.

## 준비된 도구

| 파일 | 위치 | 역할 |
|---|---|---|
| `10_tools/runtime/kmemdump.c` | 실기 | `/dev/kmem` 구간을 파일로 복사. 읽기 전용. 이미지 창 0x100000–0x20a000 밖은 `/dev/kmem` 을 열기 전에 거부 |
| `10_tools/runtime/build.sh` | 실기 | 네이티브 cc 로 빌드하고 창 밖 거부를 자가 시험 |
| `10_tools/runtime/snapshot.sh <label>` | 실기 | `sync` 뒤 `__TEXT`·`__DATA`·`__OBJC` 세 세그먼트와 `hostinfo`·`kl_util -s` 를 저장. 기존 label 은 덮어쓰지 않음 |
| `10_tools/runtime/compare_snapshot.py <label> [<label2>]` | 호스트 | 원본 파일 대조, 차이 word·zero-fill 비영 word·가장 가까운 원본 심볼·값의 소속 세그먼트, 두 스냅샷의 안정성 |

2026-09-30 실기 빌드는 경고 없이 끝났고, 창 밖 두 요청은 rc 2 로 거부됐으며, `_hz` 읽기는 100 을 돌려줬다. 분석기는 원본으로 합성한 스냅샷(무변경·변경 2 word)으로 호스트에서 시험했다.

원시 덤프(`*.bin`)와 `context.txt` 는 원본 커널 bytes 와 실기 상태라 `.gitignore` 로 제외한다. 전체 비교 보고서 `*-compare.json` 도 제외한다. R1 에서 ARP 표·UDP 제어 블록 자리의 live 값이 실기 사이트의 사설 IP 로 풀렸기 때문이다. 커밋하는 것은 값이 없는 `*-summary.json` 이며, 커밋 전 dotted 형식과 정수 형식(`a8c0`) 모두로 IP 를 검사한다.

## 실행 후보

| ID | 작업 | 실기 부하 | 답하는 것 | 답하지 않는 것 |
|---|---|---|---|---|
| R1 | 스냅샷 1 회 + 대조 | kmem 약 1 MB 읽기, 수 초 | 부팅 이미지 = 파일(`__TEXT` 일치), kmem 오프셋 = VA, 부팅 후 바뀐 `__data` word, `__bss`/`__common` 의 실제 값, `__OBJC` 의 런타임 변경 | 바뀐 이유, 어느 함수가 썼는지 |
| R2 | 몇 분 간격 스냅샷 1 회 더 | R1 과 같음 | 바뀐 word 를 안정/변동으로 분리(설정성 값과 카운터·상태 구분의 입력) | 변동의 원인 |
| R3 | R1 자료로 디스패치 표 해석 | 없음(호스트) | `_sysent`(`_nsysent` 개수), `_mach_trap_table`, `_bdevsw`, `_cdevsw`, `_vfssw`, `_idt` 의 런타임 포인터가 어느 함수 후보 시작을 가리키는지, 이미지 밖(적재된 커널 서버)을 가리키는 칸 | 특정 indirect call site 가 그 표를 읽는다는 것. 표의 끝은 다음 심볼까지라는 가설 |
| R4 | R1 자료로 `__OBJC` 변경 분류 | 없음(호스트) | `__message_refs`·`__cls_refs`(flags 0x5) 와 class/method 자료의 부팅 후 값 | ObjC runtime 의 규칙 |

R1·R2 는 같은 세션에서 이어서 할 수 있다. 오디오 시험이나 다른 실기 작업과 동시에 하지 않는다.

## R1·R2 결과 (2026-09-30)

[요약](../09_validation/runtime/x86-live/20260930-r1r2-summary.json). 두 스냅샷의 간격은 실기 시계로 301 초다.

- **전제 판정 기준을 고쳤다.** 처음 비교기는 `__TEXT` 세그먼트 전체의 일치를 요구했다. R1 에서 Mach-O 헤더의 1 바이트가 달라 전제가 거짓으로 나왔다. 전제는 **파일 기반 `__TEXT` 섹션 셋(`__text`·`__const`·`__cstring`) 전부의 일치**로 판정하도록 바꿨고, R1·R2 모두 통과했다. 따라서 부팅된 이미지의 코드·상수·문자열은 분석 기준 파일과 같고, `/dev/kmem` 오프셋은 가상주소다.
- **헤더 차이:** 파일 오프셋 0x7e4, 다섯 번째 로드 명령(`__LINKEDIT` LC_SEGMENT)의 `cmd` 필드가 파일에서 1, 실행 중 이미지에서 0 이다. R1·R2 에서 같다. 누가 왜 바꿨는지는 확정하지 않았다.
- **`__DATA`:** 원본(파일 기반 word 는 파일 값, zero-fill word 는 0)과 다른 word 를 **원본 섹션 기준**으로 센 값이다. 두 스냅샷 사이에 바뀐 word 는 590 개로 모두 `__DATA` 에 있다.

  | 섹션 | R1 | R2 까지 그대로 / 바뀜 | R2 |
  |---|---|---|---|
  | `__data` | 706 | 684 / 22 | 705 |
  | `__bss` | 586 | 248 / 338 | 585 |
  | `__common` | 2,487 | 2,273 / 214 | 2,484 |

  **정정(2026-09-30, 검토 Q0):** 처음에는 "`__data` 775 word, zero-fill(`__bss`·`__common`) 3,004 word" 로 적었다. 비교기가 zero-fill 을 `__bss` 시작(세그먼트 기준 0xb6c0)이 아니라 파일 크기 경계 0xc000 부터 세어서, `__bss` 앞 2,368 바이트(파일에서는 모두 0)의 word 가 파일 기반 쪽에 섞였다. 두 값은 저장 영역 기준이었고 섹션 기준이 아니었다. 합계 4,328 은 두 기준에서 같다.
- **`__OBJC`:** 원본과 다른 word 548 개가 7 개 섹션에 있고, R1·R2 사이 변화는 없다.
- **보고서의 "가장 가까운 앞 심볼"은 위치 표지일 뿐 소속이 아니다.** `__bss` 앞부분에는 심볼이 없어 `_version` 뒤로 잡히고, `__OBJC` 에는 주소 있는 심볼이 없어 전부 한 이름으로 뭉친다. ObjC 귀속은 R4 에서 `objc.json` 으로 한다.

## 절차 이탈 기록

R1·R2 의 도구(`kmemdump.c`, `snapshot.sh`, `compare_snapshot.py`)는 codex 계획 교차검토 없이 작성·실행했다. 사용자 지시(2026-09-30): 계산은 무조건 Python, codex 교차검토는 계획 단계에서 코딩 전에, codex 는 신뢰하지 않는다. R3·R4 부터 이 순서를 지키고, `compare_snapshot.py` 는 사후 검토 항목 Q0 으로 따로 검토한다.

## R3·R4 계획 (코딩 전, 교차검토 대상)

입력은 이미 뜬 R1·R2 덤프뿐이다. 실기는 다시 쓰지 않는다. 모든 주소·개수 계산은 Python 이다.

### 공통 분류 기준

word 의 live 값 v 를 다음 순서로 하나에만 배정한다. 앞 항목일수록 근거가 강하다.

| 등급 | 조건 | 근거 종류 |
|---|---|---|
| T1 | v 가 원본 nlist 의 `__text` 정의 심볼 주소와 같다 | 원본 바이너리 사실 |
| T2 | T1 이 아니고 v 가 Ghidra `full-pass5` 함수 후보 시작 주소와 같다 | 디컴파일러 가설 |
| T3 | v 가 `__TEXT` 범위 안이나 T1·T2 가 아니다. 후보 body 안인지 함께 적는다 | 가설 |
| D | v 가 `__DATA` 또는 `__OBJC` 범위 안이다. 원본 섹션 이름을 적는다 | 원본 섹션 표 |
| L | v 가 `__LINKEDIT` 범위 안이다 | 원본 세그먼트 표 |
| X | v 가 0 이 아니고 위 어디에도 속하지 않는다(`__PAGEZERO` 범위 포함) | 해석하지 않음 |
| Z | v 가 0 이다 | |

값이 어떤 주소와 같다는 것은 그 word 가 포인터라는 증명이 아니다. 우연히 같은 정수일 수 있으므로 보고서는 "값이 주소와 같다"라고만 쓴다.

### R3 — 디스패치 표 live 값 분류

- 대상 심볼: `_sysent`, `_mach_trap_table`, `_bdevsw`, `_cdevsw`, `_vfssw`, `_idt`, `_idt_pseudo`.
- 범위는 심볼 주소부터 **주소가 다른 다음 정의 심볼**까지로 한다. 이것은 가설이며 보고서에 그렇게 적는다. `_gdt`·`_nsysent` 처럼 범위가 4 바이트인 것은 표로 다루지 않는다.
- word 마다 파일 값·R1 값·R2 값·R1=R2 여부·파일 대비 변경 여부·위 등급을 기록한다.
- `_idt`·`_idt_pseudo` 는 포인터가 아닐 수 있는 값이다. x86 게이트 서술자 형식으로 해독하는 것은 외부 형식을 들이는 일이라 하지 않는다. 원시 값과 등급만 기록한다.
- **주장하지 않는 것:** 항목 크기(stride)·필드 의미, 어느 간접 호출 지점이 그 표를 읽는지, X 등급 값이 어느 모듈인지.

### R4 — `__OBJC` 변경 word 분류

- `objc.json` 은 로컬 SDK 헤더 `objc-class.h` 로 해석한 자료라 쓰지 않는다. 섹션 경계는 원본 Mach-O 섹션 표에서만 가져온다.
- R1 에서 원본과 다른 548 word 마다 소속 섹션, 파일 값의 등급, live 값의 등급, R1=R2 여부를 기록한다. 파일 값이나 live 값이 flags 2(문자열) 섹션을 가리키면, 원본에서 그 주소부터 NUL 까지의 bytes 를 함께 적는다.
- 집계는 (소속 섹션, 파일 값 등급·대상 섹션 → live 값 등급·대상 섹션) 쌍의 개수다.
- **주장하지 않는 것:** 필드 이름·구조체 배치·런타임 규칙.

### 산출물과 공개 규칙

- 전체 word 목록은 로컬 전용 `*-r3-full.json`·`*-r4-full.json`(gitignore).
- 커밋은 값 없는 집계 `*-r3-summary.json`·`*-r4-summary.json`. 단, T1 등급의 심볼 이름과 표 안 word 위치(offset)는 원본 바이너리에서 나온 것이라 요약에 넣는다. X 등급 값은 넣지 않는다.
- 커밋 전 IP 검사(dotted·정수 두 형식).

### 검증 방법

1. 합성 입력 시험: 원본에서 만든 가짜 스냅샷에 T1·T2·T3·D·X·Z 각 등급 값을 하나씩 심고 분류 결과가 기대와 같은지 본다.
2. 분모 대조: R3 표별 word 수가 (다음 심볼 주소 − 심볼 주소)/4 와 같은지, R4 word 수가 R1 비교 보고서의 548 과 같은지 Python 으로 확인한다.
3. 등급 배타성: 각 word 가 정확히 한 등급에 들어가는지 확인한다.

### codex 교차검토 항목 (한 호출에 한 주장)

- Q0: `compare_snapshot.py` 가 zero-fill 구간을 `file_size` 뒤부터 세는 것이 세그먼트별로 맞는가(사후 검토).
- Q1: R3 의 "다음 정의 심볼까지" 범위 규칙이 `symbols.tsv` 의 같은 주소 심볼·비정렬 심볼(`_version` 0x1e5659)에서 어긋나지 않는가.
- Q2: 등급 T1 의 기준 집합을 "섹션 번호 1 인 정의 심볼"로 잡는 것이 `symbols.tsv` 의 열 의미와 맞는가.
- Q3: R4 가 `objc.json` 없이 원본 섹션 표만으로 계획한 집계를 낼 수 있는가, 숨은 스키마 의존이 있는가.

| Q3 | 섹션 중간을 가리키는 값은 문자열의 뒷부분이나 빈 bytes 를 낸다 | 논리 확인. 실측은 구현 시 합성 시험으로 | ✅ 채택. 보고서에 그 점을 적는다 |

**채택으로 바뀐 계획:**

- 등급 **L**: v 가 `__LINKEDIT` 범위 안이다. 등급 X 는 `__PAGEZERO`·`__LINKEDIT`·이미지 세 세그먼트 밖의 0 아닌 값으로 한정한다.
- 대상 섹션 표기: 세그먼트 안이지만 어느 섹션에도 없는 주소는 `<segment>,(no section)` 으로 적는다.
- R4 의 NUL 까지 추출은 "flags 하위 바이트가 2 인 섹션을 가리킬 때"로만 조건을 적고, 추출 범위는 그 섹션의 파일 기반 끝까지로 제한한다.

## 이번 계획에 넣지 않은 것

- **이미지 밖 커널 힙 읽기**(proc·task·thread 구조체 추적). 매핑되지 않은 주소를 읽을 위험이 있고 도구의 창이 막는다. structure layout 증거가 필요하면 별도 계획과 주소별 검증 규칙을 먼저 세운다.
- **호출 단위의 인자·반환값, call site 별 간접 대상.** 중단점·추적이 필요하므로 커널 수정이나 부팅 인자(재부팅)를 요구한다. 재부팅은 사용자 몫이고, 현재 범위에서 커널 모듈 적재는 하지 않는다.
- `/dev/kmem` 쓰기, 레지스터·장치 접근, 재부팅.
- m68k 실기. 그 머신의 커널이 `03_original/m68k` 와 같은지는 별도로 확인해야 한다.

## 안전 규칙

- 읽기만 한다. 스냅샷 전에 `sync` 한다. 크래시는 루트 UFS fsck 를 부른다.
- 창 밖 요청은 도구가 거부한다. 창을 넓히려면 이 계획을 먼저 고친다.
- 실기 명령은 gcds 로, 3 분 넘는 작업은 `nohup` 분리 실행. R1 은 수 초라 해당 없음.
- 모든 주소·크기·개수 계산은 Python 에서 한다.
