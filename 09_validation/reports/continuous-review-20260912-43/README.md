# 전체 분석 인벤토리의 분모·상태 교차대조

의미 검토 원장 계획의 독립 검토가 종료 오류로 의견을 전달하지 못하여 생성기는 작성하지 않았다. 이번 산출물은 **기존 자료의 읽기 전용 집계·분류 대조**이며 함수별 의미 원장이나 전체 분석 완료 판정이 아니다.

## 도구 성공과 현재 함수 집합은 다르다

| 현재 Ghidra 분류 | IDA 성공 기록 | IDA 실패 기록 | IDA 요청 없음 |
|---|---:|---:|---:|
| 일반 함수 4,761개 | 4,517 | 244 | 0 |
| 인위적 분석 조각 492개 | 0 | 0 | 492 |

IDA 성공 총계 4,519에는 현재 함수 집합 밖의 데이터 주소 `1cde80`, `1cdea0`이 포함된다. 기존 총계를 삭제하거나 수정하지 않고, raw 도구 응답 성공과 현재 함수에 대응하는 성공을 구분했다. 이는 새로운 누락 함수를 발견했다는 뜻이 아니다. 해당 영역은 기존 gap-actions에서도 데이터로 정정되어 있었다.

Ghidra 경고 884개를 현재 C 출력에서 다시 추출해 보존 목록과 정확히 대조했다. 일반 함수에 611개, 조각에 273개가 있다. IDA 실패 중 230개에는 Ghidra 경고가 없고 14개에는 경고가 있다. 따라서 **Ghidra 경고가 없다는 이유로 IDA 실패나 의미 검토 의무를 제외하면 안 된다.** 조각의 IDA 미요청 역시 실패로 바꾸어 집계하지 않는다.

## 데이터 주소와 출처 설명의 한계

| 데이터 주소 | 보존 심볼 | 원본 DWORD 값 |
|---|---|---|
| `1cde80` | `_NXPtrValueMapPrototype` | `1cca20`, `1cca98`, `1ccb3c`, `0` |
| `1cdea0` | `_NXObjectMapPrototype` | `1cca80`, `1ccb1c`, `1ccb44`, `0` |

각 첫 세 값은 현재 일반 함수의 entry와 일치하며 보존 함수명은 각각 pointer/object용 hash·equality·free callback에 대응한다. 현재 code-unit은 각 영역을 data로 분류하고 함수 본문 소유자는 없다. IDA의 함수 형태 출력은 이 현재 분류와 양립하는 함수 검증 증거가 아니므로 별도로 남겨야 한다.

기존 `gap-actions.json`은 이들에 대해 `SDK objc/hashtable2.h`를 공통 근거로 적었다. 실제 로컬 헤더를 읽어 보니 `NXHashTablePrototype`의 선언은 있으나 `NXMapTablePrototype`, `NXPtrValueMapPrototype`, `NXObjectMapPrototype`의 직접 선언은 없다. 따라서 **그 헤더가 NXMap 상수의 정확한 선언을 직접 제공한다는 식의 근거 연결은 부족하다.** 기존 고정 파일은 수정하지 않고 이 한계를 추가 기록했다.

원본 `NXCreateMapTableFromZone`에서는 앞선 인자 세 개의 nonzero와 다음 인자의 zero를 검사하며, 네 DWORD를 저장하는 코드가 관찰된다. 선택 명령은 원본 바이트로 대조했다. 이는 데이터 구조 해석을 뒷받침하지만, 실제 prototype 헤더·정확한 호출 규약·GCC 2.7 ABI·동적 동작 검증을 대신하지 않는다. 인용이 불충분하다는 사실만으로 기존 데이터 분류가 틀렸다고 결론 내리지 않는다.

## 보존·집계 검증

- Ghidra 최종 export 15,770개를 보존 해시 목록과 재대조했다.
- IDA 성공 pseudocode 파일 4,519개의 해시와 실패 목록 244개의 원형을 확인했다.
- 전체 분석 단위 5,253개의 entry 중복 여부, 본문 크기와 범위를 계산했다. 본문 range 12,268개의 합과 합집합은 모두 824,512바이트이며 겹친 소유 바이트는 0이다. 이것은 현재 metadata의 범위 관계이지 실제 함수 경계나 의미 coverage의 증명이 아니다.
- 이전 보고서 보존 파일 569개를 확인했다. 별도 입력 225개의 식별자와 해시를 남겼다.

Ghidra 스킬에 따라 보존 자료를 읽기 전용으로 사용했고 주소·크기·개수·해시는 모두 Python으로 계산했다. 원본·DB·export·이전 보고서는 변경하지 않았다. 신규 emulator 실행, 원장 생성기/consumer, `07_kernel` 구현 및 GCC 2.7 실컴파일은 수행하지 않았다.
