# 88차 — 원본 SCSI 큐·완료 및 조건 잠금

87차는 원본 disk metadata와 요청 제출까지의 검토로 실제 진척이 있었다.
이번에는 제출된 요청의 할당·대기·해제, worker dequeue와 완료 전달,
직접 연결된 NXConditionLock 후보의 지역 계약을 검토한다.

OPENSTEP 원본 x86 바이너리, 그 바이너리의 Ghidra full-pass5 출력·참조·메타데이터,
이전 원본 분석의 보존 기록만 사용한다. 외부 프로젝트 코드와 `01_resources`,
복원 중인 `07_kernel`은 열거나 비교하지 않는다. 역사적 외부 코드 비교를 재사용하지 않는다.

Ghidra 스킬의 함수 본문·참조 대조 절차를 기존 export에 적용했다.
원본·DB·export·이전 확정 보고서는 수정하지 않는다. 실제 메서드 등록과 runtime
객체 identity가 입증되지 않은 selector→IMP 연결은 조건부로 명시한다.

독립 계획 교차검토의 새 결과는 받지 못했다. 이를 통과로 간주하거나 과거 실패
요청을 재시도·우회하지 않는다. 새 검증 프로그램/에뮬레이터/커널 코드는 작성하지 않는다.
inline Python으로 원본 바이트 디코드·유한 정수 계산·해시를 구하고 증거 JSON과
문서만 apply_patch로 기록한다. 모든 계산은 Python으로 수행한다.

doSdBuf 본문·장치 전송·scheduler primitive 전체를 이 단계에서 완료했다고 주장하지 않는다.
bzero/memset의 추가 열람은 예비 검토로 구분하며 전체 raw 검증 본문 수에 포함하지 않는다.
동적 실행·복원·구현·빌드·포팅은 범위 밖이다. 전체 원본 분석 목표는 계속 활성 상태다.
