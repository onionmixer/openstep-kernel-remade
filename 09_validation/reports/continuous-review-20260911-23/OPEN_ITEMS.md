# 잔여 분석 의무 — 보고서23 이후 상태

이 목록은 전체 분석 목표를 유지하기 위한 작업 색인이다. 유한 fixture 통과를
전체 의미 검증이나 구현 완료로 바꾸지 않는다. 이번 정상 copyout 범위만 완료된
것이며 아래 의무는 별도로 닫아야 한다.

| 의무 | 현재 근거와 남은 범위 | 완료 판단에 필요한 증거 |
|---|---|---|
| 사용자 주소 공간 | report22/23 합성 A/B root 및 정상 copyin/out 검증 | 원본 사용자 pmap 생성 결과, 비연속 물리 페이지·추가 접근 조건, 실제 문맥 전환과의 연결 |
| 전체 문맥 전환 | CR3 비교/쓰기 조각만 실행 | 스레드 선택, LDT/TSS·스택·최종 CS 전환을 원본 제어 흐름에서 검증 |
| 실제 예외 진입·복귀 | report23 vector14·EIP·CR2/부분 쓰기; report02/03은 synthetic recovery | PF error code/프레임, 실제 IDT/trap/helper/IRETD 연결과 재시작·실패 반환 상태 |
| FS/descriptor 상태 | 초기 GDT 및 일부 load/cache 시험 | POP FS 출처, alias를 통한 descriptor 쓰기, 권한·limit·비동기 상태까지 필요한 불변 조건 |
| recover 수명 | 짧은 성공 뒤 recover가 남는 원본 동작 확인 | 모든 관련 호출자/후속 trap에서의 사용·해제·수명과 비지역 복구 제어 흐름 |
| 부팅 잔여 분기 | 초기 pmap/GDT 구간 제한 실행 | 전체 i386_init, 비디오 매핑, 다른 메모리 구성, 할당 실패, 펌웨어 및 최종 CPU 상태 |
| ABI·타입·함수 경계 | 선택 함수 교정 실험과 원본 인자/반환값 근거 | 미해결 인자 귀속·간접 호출·숨은 ABI·구조체·분리 fragment/비복귀 전파를 호출자와 함께 검증 |
| CPU 부작용 표현 | CR0/CR3, IF, descriptor, FS/REP 및 RMW 모델 누락 검토 | 원본 효과를 보존하는 분석 표현을 작업 사본에 통합하고 전체 관련 소비자 회귀 검증 |
| 동시성·장치 접근 | 선택된 lock/순서/I/O 관찰 | 동적 alias, 보호 필드, 실제 경합·interrupt·MMIO·TLB/cache 효과와 오류/재시작 조건 |
| 정본과 독립 도구 대조 | 원본 Ghidra/IDA 자료 보존; 일부 사본만 교정 실험 | 검증된 교정안을 별도 최종 작업 사본에 반영·재추출, 동일 원본 입력의 IDA 검증 및 실패 원인 처리 |
| 소스 계보와 복원 명세 | 공개 소스와 원본의 부분 대응 | 채택 가능한 소스/타입/ABI 대응 및 바이너리만으로 확정할 수 없는 부분을 명시한 추적 가능한 명세 |

GCC 2.7 구현·컴파일·링크·부팅 및 후속 아키텍처는 별도 단계의 의무이다.
현재 x86 분석 fixture 통과를 그 완료 근거로 사용할 수 없다.
원래 주석·매크로·파일 배치의 유일한 복원처럼 바이너리만으로 증명할 수 없는
성질도 도구 출력이나 테스트로 확보했다고 주장하지 않는다.

다음 우선 작업은 합성 fault 주입과 CPU 모델의 실제 paging fault 관찰 사이에서
남아 있는 trap-frame/복귀 계약을 연결하는 것이다. 먼저 원본 진입·복귀 명령과
프레임 구조를 계획 단계에서 교차검토하고, 최종 CS 상태 및 예외 전달의 필요한
선행조건을 확인해야 한다. 에뮬레이터가 이를 지원하지 않으면 성공으로 대체하지
않고 지원 한계와 아직 검증하지 못한 범위를 증거로 남긴다.
