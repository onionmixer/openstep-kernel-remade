# 코딩 전 계획 및 Codex 교차검토 판정

사용자 요청: 가장 안전한 방법으로 신중하게 추가 분석하고 모든 계산은 Python으로
수행한다. 코딩 전에 Codex 교차검토를 사용하되 그 의견을 신뢰의 근거로 삼지 않는다.

## 순서와 범위

새 시험 코드 작성 전에 독립 Codex 검토자 `/root/codex_plan_crossreview`에게
읽기 전용 계획 검토를 요청했다. 검토자는 코드를 작성하거나 실행시험을 하지 않았다.
주 에이전트는 해당 원본 assembly와 선행 보고서를 별도로 읽고 아래 판정을 내렸다.
이 문서는 새 시험 코드보다 먼저 작성한다. 모델 간 동의는 정확성 증거가 아니다.

최소 범위: 원본 `_switch_context`의 root 비교/CR3 쓰기 조각과, 이후 합성 사용자
매핑에서 전체 `_copyin`/`_copyinmsg`의 DF=0 정상 경로. 커널 소스 구현, 실제 부팅,
전체 context switch, 권한 위반 및 fault 복구 검증으로 확대하지 않는다.

## 교차검토 지적과 독립 확인

| 지적 | 주 에이전트의 근거 확인 및 처리 |
|---|---|
| 같은 root와 다른 root 모두 필요 | `0018d37c.asm`의 `18d3e7`부터 `18d3f2` 직전까지 읽기/비교/분기/CR3 쓰기 확인. A→B→B→A에 초기 root→A를 포함한다. |
| directory만 복제하면 low/high 매핑이 함께 바뀔 위험 | 보고서21 bootstrap의 entry 복사와 low/high 동일 table 주소 확인. 낮은 버퍼 PDE의 table도 별도 복제하고 Python walker로 모든 시험 페이지를 검사한다. |
| 이전 fixture의 flat DS/SS는 전체 copy에 불충분 | 원본 `001860dc.asm`의 `186117..186124` DS/ES/SS 설정을 실행한다. CS는 의도적으로 flat `0x48`을 유지하고 실제 CS 전환은 제외한다. |
| `_copyin`은 인자 슬롯을 변경할 수 있음 | `189aa4/189aa7/189ac5/189ac8` 확인. 반환주소·ESP·보존 레지스터를 검사하되 인자 슬롯 전체 불변을 요구하지 않는다. |
| short 성공 recover 유지 | `189a83→189b29`, `189b6a→189c11` 및 보고서02 대조. 짧은 정상 반환의 recover 유지 자체를 오류로 판정하지 않는다. |
| memory API 좌표계 불명확 | 문서나 Codex 의견으로 단정하지 않는다. 다른 물리 페이지의 서로 다른 패턴과 원본 FS scalar 읽기부터 실행해 API 직접 읽기와 구분한다. |
| code cache와 TLB 혼동 금지 | 사용 중인 실행 helper의 `ctl_remove_cache` 호출을 기록. CR3 전환에 따른 관찰만 주장하고 하드웨어 TLB 정확성은 주장하지 않는다. |
| 역방향 복사로 일반화 금지 | 이번 대상은 copyin/copyinmsg뿐. copyout, POP FS, privilege/fault 검증은 별도 과제로 남긴다. |

## 실행 전 통과 조건

- 원본 바이너리, 기존 산출물 manifest, 정본 및 기존 실험 Ghidra 프로젝트 해시를 검사한다.
- 원본 bootstrap을 실행한 뒤 새 root와 낮은 버퍼용 table을 합성 RAM에만 복제한다.
- 사용자 A/B의 낮은 버퍼, 높은 커널 버퍼, 코드·스택·GDT·메타데이터가 의도대로
  매핑되는지 Python walker로 검사한다. 페이지 경계 양쪽 모두 검사한다.
- root 변경은 fixture register API로 대체하지 않고 선택한 원본 비교/쓰기 구간으로 실행한다.
- FS scalar 읽기 결과, API 직접 읽기 결과, 예상 물리 페이지 내용이 서로 구분되는지 먼저 검사한다.
- 게이트 실패 시 원본 결함으로 기록하지 않는다. 실패를 보존하고 fixture 원인부터 조사한다.

## 정상 경로 시험

서로 다른 사용자 매핑과 커널 매핑에 구별되는 패턴을 놓고 길이 0, 1, 15, 16,
17, 19, 31, 64 및 정렬/페이지 경계를 검사한다. 같은 root 재선택도 포함한다.
전체 목적지 버퍼, 사용자 버퍼 불변, 반환값, 반환주소/ESP, 보존 레지스터,
recover 값을 검사한다. 원본 바이트와 실제 실행 위치도 대조한다.
잘못된 단일 주소 공간 해석의 예측값과 비교하되 이는 컴파일한 C 실행으로 부르지 않는다.

결과·한계·재현성은 별도 README/JSON에 기록한다. 원본과 기존 분석 결과는 고치지
않으며 새 보고서 디렉터리에서만 작업한다. GCC 2.7용 구현 단계로 넘어가지 않는다.
