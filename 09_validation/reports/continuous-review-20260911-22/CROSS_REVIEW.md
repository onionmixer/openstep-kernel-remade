# Codex 교차검토와 독립 재확인 기록

## 코딩 전

독립 검토자 `/root/codex_plan_crossreview`가 읽기 전용으로 계획을 검토했다.
최소 CR3 선택 구간, private low page table 필요성, 혼합 CS fixture 한계,
인자 슬롯 변경 허용, short recover 유지, memory API 좌표계, TB/TLB 구분을
지적했다. 주 에이전트가 원본 및 기존 코드에서 다시 확인한 판정은 PLAN.md에 있다.
계획 교차검토 완료 후에만 새 시험 코드를 작성했다.

## 최초 실행 뒤의 추가 검토

첫 실행은 정상 복사 384조건을 통과했으나, 독립 검토자는 데이터 패턴이
페이지 간 같은 내용을 반복한다는 약점을 지적했다. 주 에이전트가 Python으로
실제 PATTERNS를 읽어 재계산한 결과 A/B/kernel 모두 `period_256 == True`,
`first_and_second_page_identical == True`였다.

이는 원본 실행 실패가 아니라 시험의 오류 검출 능력 부족이다. 초기 통과를
충분한 페이지 경계 검증으로 채택하지 않고 다음과 같이 보강했다.

- 페이지 사이 같은 위치의 모든 바이트가 다르도록 패턴 생성식을 변경했다.
- 각 컨텍스트에서 그 차이를 Python으로 직접 세고 페이지 크기와 같아야 통과시켰다.
- 두 번째 페이지가 첫 페이지에 잘못 alias된 경우의 source 예측값을 Python으로
  만들어, 실제 source 경계 횡단 사례마다 올바른 값과 달라야 통과시켰다.
- CR3 변경을 생략해 이전 root를 사용했을 때의 scalar 읽기 예측값도 분리했다.
  실제 root가 바뀌는 경우에만 관찰 결과와 달라야 통과시켰다.

최종 JSON은 이 보강을 적용해 다시 실행한 결과이다. 최초의 약한 패턴은 채택하지 않았다.

추가로 검토자가 원본 바이트 검사 범위의 표현을 지적했다. 주 에이전트가
`original_bytes()` 호출 위치를 확인했다. 이번 검사는 CR3 선택 조각, FS scalar,
전체 copy 방문 PC의 backing 바이트를 실행 후 대조한다. bootstrap/segment 설정
전체의 새 trace 검사 또는 instruction-fetch 변환의 독립 증명이라고 부르지 않는다.
bootstrap 코드의 별도 검증 근거는 선행 보고서21이고, 그것을 이번 실행의 새 검사로
중복 집계하지 않는다.

Codex의 조건부 승인이나 지적 자체를 증거로 채택하지 않았다. 원본 명령,
Python 재계산, 실제 실행 결과로 확인한 사항만 최종 보고서에 반영한다.
