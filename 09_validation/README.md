# 검증

현재 전체 x86 분석 자료의 검증은 [전체 분석 보고서](reports/full-analysis/README.md)를 참조한다.
이는 자료 확보의 검증이며 복원 커널의 기능·빌드 검증과 구별한다.

- `static/`: 심볼/섹션/ABI/layout/차분 결과.
- `boot/`: 기존/복원 커널의 부트 로그와 플랫폼 설정.
- `regression/`: VM, IPC, syscall, filesystem, network, DriverKit/모듈 결과.
- `images/`: 로컬 테스트 디스크/스냅샷. 커밋 제외.
- `reports/`: 결과 명세, 미해결 차이, 준비 검증 결과. 100 MiB 를 넘는 `*-cases.json` 여섯 개는 `.json.gz` 로 커밋한다(`gunzip -k` 로 원본 이름 복원).

`templates/run.md`를 실행 기록의 기본 형식으로 사용한다.
준비 검증(파일/해시/인벤토리)이 커널 기능 검증으로 집계되지 않도록 분리한다.
원본 커널과 복원 커널을 같은 플랫폼에서 비교하며 실패와 미실행도 기록한다.
최종 커널은 GCC 2.7로 전체 컴파일·링크한 산출물이어야 한다.
정확한 컴파일러/target·옵션·전체 빌드 로그를 기록하고, 검증한 커널 해시와 연결한다.
현대 컴파일러만으로 성공한 결과는 GCC 2.7 호환성 완료로 판정하지 않는다.
